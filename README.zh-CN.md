# 技能打包与上架流程

[English](README.md) | [简体中文](README.zh-CN.md)

> 把本地技能或公司内部方法论，整理、脱敏、打包成别人可以安装的产物。

## 这是什么

这不是一个打包命令。对外分发的包有它自己的约束，普通压缩包不管这些 —— 字段名要合规、禁止二进制内容、要过审核，以及一个硬要求：敏感内容不能跟着包出去。

这些都写在技能里了，包括脱敏那一步 —— 恰恰是赶时间的时候最容易被跳过的一步。

## 为什么开源

我们经常把内部方法打包给团队用，每次都重新摸一遍同样的字段约束，重新人工核对同一张清单。

写下来之后流程变短了，更有用的是，脱敏那一步变成了不可跳过的。流程本身是通用的，里面的例子都是占位符。

## 能做什么

- **字段规范。** 哪些元数据字段必填、哪些选填、每个字段接受什么值 —— 对着当前平台规则核，不靠记忆。
- **压缩包的硬约束。** 某些类型的内容会导致直接驳回。这条规则在构建时就执行，而不是等上传被拒了才发现。
- **一道脱敏工序。** 提交之前自动扫一遍包，查凭据、内部名称和绝对路径。
- **两个辅助脚本。** 一个审计包，一个构建包。
- **错误对照。** 常见的驳回原因，以及每条实际意味着什么。
- **审核流程写明。** 查什么、按什么顺序查。

## 环境要求

Python 3

## 安装

```bash
git clone https://github.com/<你的用户名>/skillhub-publish-pack.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\skillhub-publish-pack\` |
| macOS / Linux | `~/.workbuddy/skills/skillhub-publish-pack/` |

没有构建步骤，重启对话即生效。

## 怎么用

直接说要打包或者上架：

- "把这个做成技能发上去"
- "给团队打包一下这个"
- "上架有什么要求"

它会先跑审计、再构建、然后走提交。

## 注意与边界

1. **脱敏不是可选项。** 就是这一步，决定了"图个方便"和"出一次事故"的区别。技能把它做成一道关卡，而不是一句建议。
2. **字段规则会变。** 平台要求不是冻结的。技能查的是当前规则，不是缓存下来的清单。
3. **二进制内容会被拒。** 图片、压缩包、可执行文件都应该放在包外面。
4. **里面的例子是占位符。** 它们用来说明一个合规的包长什么样，不是生产内容。
